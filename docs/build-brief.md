## Code rules (security and conventions)
- Match the surrounding code: procedural PHP, `require 'auth.php'; require 'config/db.php';` at the top of a page, `h()` for every printed value, prepared statements for every value that reaches SQL (a SQL fragment may only come from a fixed whitelist), POST + `verify_csrf()` + `csrf_field()` for every change, `require_login()` / `require_staff()` / `require_admin()` for access (roles are re-read from the DB), `flash('ok'|'err', msg)` + redirect after POST. Validate everything server-side; the form's own checks can be bypassed. Never trust ids from the URL: check ownership. No `eval`, no shell, no file writes from user input. Money = DECIMAL, shown with `money()`.
- Atomic updates: put the previous state in the UPDATE's WHERE clause and check `affected_rows` (see `order-action.php`).
- Shared helpers in `includes/helpers.php` (already there): `money`, `order_no`, `cover_html`, `flash`, `cart_ids`, `order_stage`, `cancel_order`, `expire_unpaid_orders`, `notify($conn,$userId,$kind,$message,$link)`, `unread_notifications`, `bundle_discount($rent,$count)` (3 books 10%, 4+ 15%, on rent only), `AUTO_LOST_DAYS` (14), `rating_text`, `zone_of/zone_class/zone_letter`, `icon`. Put YOUR new shared functions in your own `includes/<yourname>.php` (`require_once __DIR__ . '/<yourname>.php'`), not in helpers.php, unless your brief says you own helpers.php.
- Schema v3 is already in `sql/schema.sql` and `sql/migrate_v3.sql` (tables `lib_reviews lib_wishlist lib_coupons lib_coupon_uses lib_notifications`; columns `lib_orders.coupon_code`, `lib_orders.discount_total`, `lib_books.featured`).
